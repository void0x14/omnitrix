# Warp (Agent modu / Warp Agent CLI) — Feature Ekstraksiyon Raporu (RE tabanlı)

Kaynaklar: Warp resmi blog (block-model-behind-warps-agentic-development-environment 2026-04-29, how-warp-works 2021, agent-mode 2024, introducing-the-warp-agent-cli 2026-08-04), warp.dev/agent-cli + docs.warp.dev/agents, lushbinary.com Warp Rust & GPU deep dive, Speedscale "What the Warp Terminal Sends Home" (2026-04-20, TLS interception + packet capture), HN tartışmaları (47947121, 42247583, 34346933), github warpdotdev/warp issues (#1346 spyware/Segment). Not: Warp 2026-04'te AGPL-3.0 açık kaynak oldu — istemci kodu denetlenebilir; bu rapor RE + açık kaynak + egress capture karışımı.

## 1. Kimlik (bilinen mimari)

- **Çekirdek:** Tamamen Rust; GPU tabanlı rendering (wgpu → Metal/Vulkan/DX12), custom UI framework (Nathan Sobo, Flutter esinli element tree), Alacritty'den fork'lanan grid modeli.
- **Block modeli:** Geleneksel karakter grid'i yerine **BlockList** — tipli bloklar (terminal bloğu = komut+çıktı; rich content bloğu = agent konuşması/diff/reasoning). Shell entegrasyonu: bash/zsh/fish/PowerShell bootstrap script'leri `precmd`/`preexec` hook'larıyla DCS escape sequence + JSON event gönderir → Warp blok sınırlarını bilir. Blok yükseklikleri SumTree'de (O(log n) viewport sorgusu); çıktı FlatStorage'da (packed buffer + byte-offset styling, insert yok — scrollback için yeterli); fullscreen programlar (vim/less) alt-screende ayrı GridStorage.
- **Agent katmanı:** 2024'te Agent Mode (terminal içi LLM ajanı); 2026-08'de **Warp Agent CLI** — standalone, her terminalde çalışan CLI. Mux mimarisi: agent ile shell arasında tmux benzeri PTY katmanı; agent "blok" bilincine sahip (terminal input/output'unu native anlıyor).
- **Model yönlendirme:** İstemci asla provider'a direkt konuşmaz; tüm AI trafiği `app.warp.dev` üzerinden (protobuf), routing sunucu-taraflı (cost/quality/speed puanı), ~25 model / 4 provider. Oz platformu: cloud agent orkestrasyonu, trigger/schedule/integration.
- **Egress:** RudderStack analytics (Amplitude'a), Sentry (`o540343.ingest.sentry.io`), `/analytics/block` (komut+çıktı+cwd), `/ai/multi-agent`, `/ai/passive-suggestions` (protobuf). Core API çağrıları `HTTP_PROXY`'yi BYPASS ediyor + rustls `NoKeyLog` (SSLKEYLOGFILE devre dışı) — normal inspection araçları göremiyor.

## 2. EN İYİ feature'lar (ÇAL listesi)

1. **Blok bilinçli agent (BlockList + SumTree):** agent konuşması, tool call'ları, diff'ler ve agent'ın kendi çalıştırdığı shell komutları AYNI modelde, tek blok akışında; view katmanı zero-height ile gizleme (agent çalıştırdığı komutlar konuşma görünümünde compact summary, istenince expand). Terminal bloğu seç/kopyala/paylaş/ara — grid'de imkansız olan affordance'lar. Bu, agent UI'ı için şimdiye dek görülmüş en temiz veri modeli.
2. **Mux mimarisi (tmux benzeri PTY katmanı):** agent fullscreen TUI programlarını (sqlite, mysql, python REPL) sürebilir, REPL içinde komut yazdırabilir; session dizin değişikliklerinde korunur; SSH üzerinden **uzakta binary kurmadan** çalışır. "Agent shell'de kendi terminalini kontrol eder" — diğer harness'lerin hiçbirinde yok.
3. **Natural language detection:** yerel çalışan classifier girişin komut mu prompt mu olduğunu ayırt eder; sınıflandırma sırasında hiçbir şey makineden çıkmaz (yalnızca agent'a gönderilecek şey onayla gider). `!` ile explicit shell escape de var.
4. **Orchestration agent + cross-harness delegation:** task'ları subagent'lara böler, ok/ok yön tuşlarıyla orchestrator↔subagent session'ları arasında geçiş; cloud'a devir (laptop kapanınca devam); Warp cloud üzerinden **Claude Code ve Codex harness'lerine bile** delege edebilir. Multi-model auto-routing + custom router tanımlama (takım paylaşımı).
5. **Görünürlük / onay kontrolü:** agent her komutu önce onaya sorar; context toplama şeffaf (git branch gerekiyorsa `git branch` çalıştırıp çıktısını okumayı teklif eder); çıktı okuma yalnızca yetki verilen komutlar için. Agent çalıştırdığı her komut blok olarak görünür — "neye izin verildi" her zaman ekranda.
6. **Gizlilik mühendisliği öğeleri:** `ObfuscateSecrets` (çıktıda secret redaction), telemetry toggle (`isTelemetryEnabled`, kapatınca `/analytics/block` verisi gitmiyor — Speedscale doğruladı), "View network logging" (telemetry isteklerini canlı gösteren ayar), kapsamlı yayınlanmış telemetry tablosu, ve artık AGPL-3.0 açık kaynak istemci (denetlenebilir).
7. **Block bazlı oturum sürekliliği:** her blok komut+cwd+timestamp+exit code+duration saklar; Agent Mode çıktıyı "block ID ile" referanslar (scrollback kazımak yerine). Şarj edilebilir, linklenebilir, paylaşılabilir bloklar.
8. **Ajan yeteneği genişletme:** skills, rules, plan, MCP server desteği; autocomplete komut önerileri (tab) — agent CLI'da bile.

## 3. Dezavantajlar (LOBOTOMİ listesi — kanıtlı)

1. **"Command'ların hepsi dışarı gidiyor" (Speedscale capture):** `/analytics/block` endpoint'i — her komut, çıktısı, cwd, exit code, shell detayı hesabına bağlı olarak Warp sunucusuna gönderiliyor. `export AWS_SECRET_ACCESS_KEY=...`, `curl -H "Authorization: Bearer ..."`, `ssh user@prod-db` gibi komutlar aynı kanaldan geçiyor. Secret redaction "unconditional" iddiasına rağmen çıktıdaki credential pattern'leri güvenilir yakalanamıyor (yazarın kendi itirafı).
2. **AI context sızıntısı:** her AI etkileşimi tüm `AGENTS.md`'yi + `~/.claude/skills/` altındaki TÜM skill tanımlarını (capture'da 24+, dahili tool entegrasyonları dahil) protobuf blob olarak gönderiyor. Skill dosyaları genelde repo içi özel bilgi taşır.
3. **Server-side routing — kontrol kullanıcıda değil:** bir sohbette prompt'lar GPT-5.2'ye ve GLM 5'e (Zhipu AI — Çin şirketi) gidebiliyor; client hiçbir zaman OpenAI/Anthropic'e direkt konuşmuyor. Kullanıcı hangi modelin neyi gördüğünü yalnızca Warp'a güvenerek biliyor.
4. **Gözden kaçan egress (savunma mühendisliği açısından en kötüsü):** core API çağrıları `HTTP_PROXY`'yi bypass ediyor + rustls `NoKeyLog` SSLKEYLOGFILE'ı devre dışı bırakıyor → Charles/Proxyman/proxymock göremiyor, raw pcap çözülemiyor. Kurumsal inceleme ancak root'lu transparent TLS interception ile mümkün (hosts + CA kurulumu). AI endpoint'leri protobuf, JSON değil.
5. **Startup telefon evi (HN capture):** pencere görünmeden 5 HTTP isteği (1 version check, 1 LLM model list, 3 RudderStack telemetry event'i — persistent UUID + OS + Warp versiyonu). Telemetry opt-out "kapatıldıktan sonra restart'ta tekrar açılıyor" raporu; ~7.000 satırlık telemetry event dosyası. Tarihsel: #1346 "spyware sending data to Segment" (2022) + zorunlu login (2024'e kadar sürdü).
6. **SaaS kilidi ve fiyatlandırma:** agent abonelik gerektiriyor ($18/ay), her şey app.warp.dev'e bağlı; login/hesap zorunluluğu geçmişi (HN'de uzun tartışma); telemetry kapatılsa bile AI özellikleri context'i hep gönderir (beklenen ama net belgelenmeli).
7. **GPU rendering karmaşıklığı:** wgpu + shader pipeline + custom UI framework — bir terminal için ağır bağımlılık yığını; WASM/headless taşınabilirlik zor (2021'de kendi itirafları: "WASM'i düşünmedik" hatası). Linux'ta Vulkan zorunlu, eski GPU'lar dışlanır.
8. **Alt-screen uyumsuzluğu:** vim/less gibi fullscreen programlar block modelinin DIŞINDA — blok sürekliliği alt-screen kullanımında kayboluyor; agent TUI uygulaması sürerken model ile blok listesi arasındaki senkron yüksek karmaşıklıkta.

## 4. omnitrix için öneri

- **Block modelini al (UI'ın omurgası yap):** komut+çıktı bloğu ve agent konuşma bloğu aynı listeye; SumTree yükseklik indeksi (O(log n) viewport); FlatStorage tarzı packed buffer; zero-height gizleme ile "agent komutu compact summary" görünümü. Grid'de değil, bloklarda düşün — bu model agent çağında kazanıyor.
- **Block ID ile context referansı:** agent'a "son 3 blok" yerine "block #142'nin çıktısı" ver — hem token verimli hem model için net. Çıktıyı scrollback'ten kazımak yok.
- **Yerel NL classifier'ı taklit et:** komut vs prompt ayrımı makinede kalmalı; sınıflandırma hiçbir telemetry içermemeli. Mux PTY katmanını (agent'ın fullscreen TUI/REPL kontrolü) uzun vadeli hedef yap — fark yaratan tek feature bu.
- **YAPMA:** /analytics/block benzeri "her komut + çıktı + cwd dışarı" modeli; omnitrix'te telemetry varsa event-based ve kapsamı dar olsun; komut içeriği ve çıktı asla telemetry'ye girmesin.
- **YAPMA:** HTTP_PROXY bypass + NoKeyLog kombinasyonu — kullanıcının denetim araçlarını (proxy, SSLKEYLOGFILE) bilerek engellemek güven ilişkisini öldürür; egress kurumsal politikayla görülebilir kalmalı.
- **YAPMA:** tüm AI trafiğini kendi sunucundan geçirme (server-side routing) — omnitrix BYOK/model-seçimini istemcide tutsun; "hangi modele ne gitti" her zaman istemci tarafında kanıtlanabilir olsun (Claude Code'un istemci-tarafı provider yönlendirmesi + Cursor'un sunucu kilidinin ortası).
- **Skill/AGENTS.md sızıntısına dikkat:** omnitrix kendi rules/AGENTS.md içeriğini modele gönderirken kullanıcıya "ne gönderiliyor" görünürlüğü ver (komut-başına değil, özet).
- **Telemetry'yi "kapat → restart'ta açık" davranışından arındır:** opt-out kalıcı olsun (Speedscale'in doğruladığı tek olumlu Warp davranışı olan isTelemetryEnabled modelini bile geride bırak: varsayılan kapalı, opt-in).
